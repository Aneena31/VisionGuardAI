# New Claim Scoring Upload + LLM Test Case

## Objective
Verify that New Claim Scoring accepts a real uploaded claim file, runs the full scoring pipeline, and returns an AI summary generated by the configured LLM.

## Preconditions
- API is running at `http://localhost:8000`.
- UI is running at `http://localhost:3000`.
- `OPENAI_API_KEY` and `OPENAI_MODEL` are configured in `.env`.
- ML artifacts exist in `artifacts/`.

## Test Data
- `data/Sample_Data_for_ML.xlsx`

## Steps
1. Open `http://localhost:3000/scoring`.
2. Click `BROWSE FILES`.
3. Select `data/Sample_Data_for_ML.xlsx`.
4. Wait for the scoring job to complete.
5. Review the AI Investigation Summary section.

## Expected Result
- The file picker opens when `BROWSE FILES` is clicked.
- The claim file is submitted to `/visionguard/scoring/jobs` as multipart form data.
- The scoring job reaches `100% Complete`.
- The result page shows a fraud score, risk level, rules/statistical/ML sections, and an AI summary.
- The AI summary badge shows `LLM gpt-4o-mini` or the configured model.
- API result contains:

```json
{
  "analysis": {
    "aiSummary": {
      "llmGenerated": true,
      "model": "gpt-4o-mini"
    }
  }
}
```

## Failure Indicators
- `BROWSE FILES` does not open a file picker.
- Upload returns a 4xx or 5xx response.
- Job remains stuck before completion.
- AI summary shows `FALLBACK SUMMARY`.
- `llmGenerated` is `false` or missing.

## API Smoke Test
```powershell
$createdRaw = curl.exe -s -X POST -F "file=@data/Sample_Data_for_ML.xlsx" http://localhost:8000/visionguard/scoring/jobs
$created = $createdRaw | ConvertFrom-Json
$jobId = $created.data.jobId

do {
  Start-Sleep -Seconds 1
  $status = Invoke-RestMethod -Uri "http://localhost:8000/visionguard/scoring/jobs/$jobId"
} while ($status.data.status -notin @("completed", "failed"))

Invoke-RestMethod -Uri "http://localhost:8000/visionguard/scoring/jobs/$jobId/result" | ConvertTo-Json -Depth 10
```
